# CI on MR, Vercel Production on `main` (Preview opt-in)

Two pipelines: a GitHub Actions **MR checks** workflow (typecheck, lint, test, build, migration lint, secret scan — generators mocked, no prod secrets) gates merge; **Vercel Git integration** deploys **Production when `main` updates**. A small **post-merge** Actions job applies Supabase migrations (`SUPABASE_DB_URL`) and runs prod smoke when `PROD_BASE_URL` is set.

**Preview / branch builds are not automatic** — founder can trigger a Preview manually when useful. See [ADR-0017](./0017-vercel-main-only.md).

**Why:** Keep MR checks fast/deterministic and spend-free; let Vercel own Production deploys; keep DB migration + smoke explicit. Local-first stays primary; CI is the net.

**Rejected:** Custom Action doing the Vercel build. Running real model/video generation in CI. Applying migrations inside Vercel build. Auto Preview on every PR as the review loop.
